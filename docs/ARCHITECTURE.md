# SolanaAI Lend — Архитектура

Этот документ объясняет как устроен проект — от самых основ до технических деталей. Написан так, чтобы человек без опыта в блокчейне, ML и AI мог понять каждый компонент.

---

## Часть 1: Основы (для тех кто не в теме)

### Что такое блокчейн?

Представьте общую тетрадку которую видят все участники. Когда кто-то пишет запись (транзакцию) — её видят все, и стереть или изменить нельзя. Это и есть блокчейн — распределённая база данных где все записи неизменяемы и публичны.

**Solana** — это один из блокчейнов. Его особенности:
- Быстрый: транзакция подтверждается за 0.4 секунды (у Ethereum — 12 секунд)
- Дешёвый: одна транзакция стоит $0.00025 (у Ethereum — $1-50)
- Высокая пропускная способность: 65,000 транзакций в секунду

### Что такое смарт-контракт?

Обычный контракт: "Если ты не вернул деньги через месяц, банк заберёт залог."
Смарт-контракт: то же самое, но **автоматически**. Программа на блокчейне которая исполняет условия без посредников.

На Solana смарт-контракт называется **программа**. Она написана на языке Rust с фреймворком Anchor.

### Что такое DeFi?

**DeFi** (Decentralized Finance) — финансовые сервисы без посредников. Вместо банка — смарт-контракт.

**Лендинг** — самый популярный вид DeFi:
1. **Лендер** (вкладчик) кладёт деньги в общий "котёл" (пул)
2. **Заёмщик** берёт деньги из пула под залог
3. Заёмщик платит проценты → они идут лендеру
4. Если залог обесценился → позиция **ликвидируется** (залог продаётся чтобы вернуть долг)

Всё автоматически, без банка, 24/7.

### Ключевые термины

| Термин | Простое объяснение |
|--------|-------------------|
| **Пул ликвидности** | Общий "банк" куда лендеры кладут деньги, а заёмщики берут |
| **Утилизация** | Какой % пула сейчас занят заёмщиками. Если 50% — половина денег "работает" |
| **Процентная ставка** | Сколько % в год платит заёмщик за использование денег |
| **Залог (Collateral)** | SOL который заёмщик оставляет как гарантию. Обычно 120-200% от суммы займа |
| **Health Factor** | "Здоровье" позиции. Больше 1.5 = безопасно. Меньше 1.0 = ликвидация |
| **Ликвидация** | Когда залог упал в цене и его продают чтобы вернуть долг |
| **PDA** | Программный адрес на Solana — аккаунт которым управляет только программа |
| **TX (транзакция)** | Одна операция на блокчейне (перевод, займ, и т.д.) |

### Что такое ML (Machine Learning)?

Обычная программа: `if price > 100: buy`. Вы пишете правила руками.

ML-модель: вы даёте ей тысячи примеров прошлых данных, и она **сама находит закономерности**. Например: "когда RSI > 70 И объём торгов растёт в 3 раза → цена обычно падает".

В нашем проекте ML модели анализируют рынок и предсказывают тренды, риски и аномалии.

### Что такое AI (Gemini)?

AI (GPT, Gemini) — это языковая модель которая понимает текст и контекст. Мы даём ей отчёт с 20+ метриками и просим: "какую ставку поставить?" Она анализирует ВСЁ вместе и выдаёт решение с объяснением.

Мы используем **Google Gemini 2.0 Flash** — быстрая и дешёвая модель.

## Часть 2: Как работает наш протокол

### Общая картина

```
ЛЕНДЕР (вкладчик)          ЗАЁМЩИК
   |                          |
   | кладёт aiUSDC            | берёт aiUSDC под залог SOL
   v                          v
+------------------------------------------+
|          СМАРТ-КОНТРАКТ (Solana)          |
|  Пул: $1730 депозитов, $800 займов       |
|  Залог: 18 SOL                            |
|  Ставка: 15% (устанавливает AI)          |
+------------------------------------------+
              ^
              | каждые 2 мин
+------------------------------------------+
|            AI AGENT (Python)              |
|  CoinGecko -> индикаторы -> ML модели    |
|  -> Gemini AI -> решение -> TX на Solana |
+------------------------------------------+
```

### Пример: как AI меняет ставку

1. **Ситуация**: утилизация пула выросла с 30% до 60% за час (много заёмщиков)
2. **AI видит**:
   - Утилизация 60% и РАСТЁТ (тренд = rising)
   - RSI = 72 (перекупленность — скоро может быть коррекция)
   - Risk score = 45 (средний)
3. **AI решает**: повысить ставку с 5% до 7%
   - Почему: высокая утилизация → пул может закончиться → ставка выше → заёмщики возвращают → утилизация падает
4. **Контракт проверяет**: 7% в рамках [1%, 20%]? Да. Изменение < 20%? Да. Cooldown прошёл? Да.
5. **TX отправляется** на Solana → ставка обновлена on-chain

### Пример: как работает ликвидация

1. Боб положил 1 SOL залог ($80) и занял $50
2. SOL упал с $80 до $55
3. Health Factor = ($55 * 10000) / ($50 * 12000 / 10000) = 0.92 < 1.0
4. Любой (keeper) может вызвать `liquidate`:
   - Keeper погашает $20 долга Боба
   - Keeper получает SOL на $21 (5% бонус) + $0.20 (1% keeper reward)
   - Боб сохранил $30 + оставшийся SOL (вместо потери всего)
5. Health Factor Боба: теперь 1.3 → позиция спасена

### 3.2 AI Agent (Python)

**Что это**: Python программа которая каждые 2 минуты анализирует рынок и отправляет транзакции.

**Где лежит**: `ai-agent/`

**Структура**:
```
ai-agent/
  main.py                  — точка входа (3 процесса)
  config.py                — настройки
  agent/
    orchestrator.py        — главный цикл (связывает всё)
    data_collector.py      — сбор данных (CoinGecko, Solana RPC)
    quant_engine.py        — RSI, MACD, Bollinger, ATR, EMA
    ai_engine.py           — Gemini AI + ML-only fallback
    sentiment_engine.py    — анализ новостей через Gemini
    preemptive_engine.py   — превентивные действия (6 триггеров)
    validator.py           — проверка решения (11 правил)
    tx_builder.py          — построение и отправка TX на Solana
    decision_logger.py     — логирование в SQLite
    utilization_curve.py   — Aave-style формула оптимальной ставки
  models/
    trend_predictor.py     — RandomForest (up/down/sideways)
    anomaly_detector.py    — IsolationForest (аномалии)
    volatility_model.py    — EWMA (волатильность)
    risk_scorer.py         — композитный риск (0-100)
    crash_detector.py      — вероятность крэша (6 сигналов)
    utilization_predictor.py — прогноз утилизации
```

**Цикл AI агента (упрощённо)**:
```
Каждые 2 минуты:
  1. Получить цену SOL с CoinGecko           (data_collector)
  2. Получить состояние пула с Solana         (data_collector)
  3. Посчитать RSI, MACD, Bollinger           (quant_engine)
  4. Запустить ML модели                       (models/)
  5. Проверить вероятность крэша               (crash_detector)
  6. Проанализировать новости                  (sentiment_engine)
  7. Спросить Gemini: "какую ставку поставить?" (ai_engine)
     (или ML-only fallback если Gemini не отвечает)
  8. Проверить решение                         (validator)
  9. Обновить цену SOL на блокчейне            (tx_builder)
  10. Отправить update_parameters TX            (tx_builder)
```

## Часть 4: ML модели (подробно)

### Что такое каждая модель и зачем она нужна

**1. RandomForest (trend_predictor.py)**

*Аналогия*: опросить 50 экспертов "цена пойдёт вверх или вниз?" Каждый смотрит на разные факторы (RSI, объём, тренд) и голосует. Побеждает большинство.

*Техническое*: 50 деревьев решений (decision trees), каждое обучено на случайном подмножестве данных. Классификация: up / down / sideways. Accuracy ~34% (лучше случайного для 3 классов = 33%).

*Входные данные (features)*:
- Последние 3 return'а цены (lag_1, lag_2, lag_3)
- RSI, MACD histogram, Volume ratio, Price/SMA20, Bollinger width, Volatility, EMA signal

*Выходные данные*:
```json
{
  "direction": "down",
  "probabilities": {"up": 0.31, "down": 0.37, "sideways": 0.32},
  "feature_importance": {"rsi": 0.23, "volume_ratio": 0.19}
}
```

**2. IsolationForest (anomaly_detector.py)**

*Аналогия*: если в толпе людей один ведёт себя странно — его легко изолировать. IsolationForest изолирует "странные" данные (flash crash, pump, необычный объём).

*Как работает*: строит случайные деревья и смотрит сколько разделений нужно чтобы изолировать точку. Мало разделений = аномалия.

*Contamination*: 0.05 — модель считает что ~5% данных аномальные.

**3. EWMA Volatility (volatility_model.py)**

*Аналогия*: "Насколько сильно цена дёргается?" Если обычно цена меняется на 1% в час, а сейчас на 5% — волатильность высокая.

*Формула*: `variance_t = 0.94 * variance_{t-1} + 0.06 * return_t^2`
Старые данные "забываются" (вес 0.94), новые "важнее" (вес 0.06).

*Режимы*: low (<1%), medium (1-3%), high (3-6%), extreme (>6%)
Extreme → AI повышает залог до максимума.

**4. CrashDetector (crash_detector.py)**

*Аналогия*: "Есть ли признаки надвигающегося обвала?"

*Почему не ML-модель*: крэши случаются редко (может 3-5 за год). ML-модель нельзя нормально обучить на 3 примерах — будет overfitting. Поэтому используем rule-based систему из 6 сигналов.

*6 сигналов*:
| Сигнал | Что смотрим | Порог |
|--------|------------|-------|
| Price momentum | Цена упала на 5% за 4 часа | +30 баллов |
| Volume spike | Объём торгов в 3 раза выше среднего | +20 баллов |
| Consecutive red | 5+ часовых свечей подряд красные | +20 баллов |
| SMA deviation | Цена ниже 20-часовой средней на 5% | +15 баллов |
| Short volatility | Волатильность за 1 час > 3% | +15 баллов |
| Trend acceleration | Падение ускоряется (вторая производная) | +10 баллов |

*Итого*: 0-100 баллов. >50 → повышаем ставку. >80 → замораживаем протокол.

**5. RiskScorer (risk_scorer.py)**

*Аналогия*: "Один общий уровень опасности" — как индекс страха (VIX) для нашего протокола.

*Формула*: взвешенная сумма 5 компонентов:
```
risk = 0.25 * volatility_risk
     + 0.20 * trend_risk
     + 0.25 * utilization_risk
     + 0.15 * anomaly_risk
     + 0.15 * liquidity_risk
```

*Уровни*: low (<25), medium (25-50), high (50-75), critical (>75)

**6. UtilizationPredictor**

*Аналогия*: "Сколько % пула будет занято через час?"

Используется для расчёта оптимальной ставки по кривой Aave.

## Часть 5: Безопасность (7 уровней)

### Почему столько уровней?

Потому что AI может ошибиться. Gemini может "галлюцинировать". API может лечь. Цена может быть манипулирована. Каждый уровень ловит свой тип ошибки:

```
Уровень 1: ПРОМПТ → ловит "глупые" решения Gemini (ставка 500%)
Уровень 2: VALIDATOR → ловит выход за рамки (rate < min)
Уровень 3: КОНТРАКТ → финальная проверка on-chain (невозможно обойти)
Уровень 4: FREEZE → кнопка паники (AI или authority)
Уровень 5: AUTO-RATE → если AI умер, контракт сам защищает ликвидность
Уровень 6: INSURANCE → если ликвидация не успела → фонд покроет bad debt
Уровень 7: GUARDRAIL PDA → параметры защиты нельзя изменить без authority
```

### Что если Gemini упадёт?

```
Gemini Online  → полный pipeline, confidence 70-90
Gemini Down    → ML-only fallback (utilization + risk + trend → решение)
Всё умерло     → on-chain auto-rate (контракт сам повышает ставку)
```

Протокол **НИКОГДА не останавливается**.

### Что если SOL упадёт на 40%?

1. CrashDetector видит сигналы ЗАРАНЕЕ (volume spike, consecutive reds)
2. Preemptive Engine повышает collateral ratio +10%
3. Если здоровье позиций < 1.0 → автоматическая ликвидация
4. Keeper получает бонус 5% за ликвидацию → мотивация
5. Если ликвидатор не успел → Insurance Fund покрывает bad debt
6. Withdrawal rate limit не даёт одному юзеру вывести весь пул

## Часть 6: Как AI учитывает утилизацию

### Тренд утилизации

AI хранит последние 10 значений утилизации и отслеживает тренд:

```
Утилизация:  30% → 40% → 55% → 65%  (rising)
Действие:    AI повышает ставку АГРЕССИВНО (+1.5%)
Почему:      Заёмщики разгоняются, пул может закончиться

Утилизация:  65% → 55% → 45%  (falling)
Действие:    AI снижает ставку МЯГКО (-0.5%)
Почему:      Не хотим осцилляцию (ставка прыгает туда-сюда)

Утилизация:  50% → 50% → 51%  (stable)
Действие:    AI двигает ставку к оптимальной по Aave-кривой
Почему:      Рынок стабилен, можно оптимизировать
```

### Aave-кривая (optimal rate)

```
Если util < optimal (80%):
  rate = base + (util / optimal) * slope1
  (линейный рост, мягкий)

Если util > optimal (80%):
  rate = base + slope1 + ((util - optimal) / (1 - optimal)) * slope2
  (экспоненциальный рост, резкий)
```

AI использует эту формулу как ориентир, но может отклоняться на основе ML сигналов.

## Часть 8: Новые фичи (Батчи 5-8)

### Model Reputation (самообучающийся AI)

AI не статичный — он отслеживает точность каждой модели:
```
После каждого цикла:
  1. Сравнить предсказание с реальностью
     trend_predictor сказал "down" → цена упала? → accuracy +1
  2. Пересчитать веса
     Точная модель → больше влияния на решение
     Плохая модель → меньше влияния (но не 0, floor 10%)
  3. Логировать
     "Reputation: trend=73% anomaly=50% volatility=62% risk=80% crash=50%"
```

### Dynamic LTV (AI адаптирует залог по волатильности)

```
Волатильность   Режим     Collateral Ratio    Что происходит
< 1%           Calm       -5% от текущего     Привлекаем заёмщиков
1-3%           Normal     без изменений       Стандарт
3-6%           Storm      +10%                Защита
> 6%           Extreme    +20%                Максимальная защита
```

AI делает это АВТОМАТИЧЕСКИ каждые 2 мин, основываясь на EWMA volatility model.

### Credit Score (on-chain кредитный рейтинг)

5 факторов → score 0-100 → tier (Bronze/Silver/Gold/Platinum):
```
Фактор              Макс баллов   Пример
Возраст аккаунта       20          3+ дня = 20
Количество операций    20          20+ = 20
Надёжность возврата    20          Нет долга = 20
Без ликвидаций         20          Никогда = 20
Размер позиции         20          2+ SOL = 20

Platinum (90+): залог -15%, ставка -10%
Gold (70-89):   залог -10%, ставка -5%
Silver (50-69): залог -5%, ставка -2%
Bronze (0-49):  стандартные условия
```

### Liquidation Predictor (Monte Carlo)

Вместо "ликвидация когда health < 1.0" — предсказываем ЗАРАНЕЕ:
```
1. Берём текущий health factor и волатильность
2. Генерируем 500 случайных ценовых путей (random walk)
3. Считаем: в скольких путях health упал ниже 1.0?
4. Результат: "1h: 0%, 4h: 2%, 24h: 12%"
5. Если 24h > 30% → показываем warning + рекомендацию
```

### Adaptive Cooldown (crisis mode)

```
Нормальный режим:        Кризис:
  Cooldown: 60 сек         Cooldown: 30 сек (crisis_cooldown.max(30))
  Max change: ±20%         Триггер: crash_prob > 80% → AI activate_crisis
                           Auto-expire: через 30 мин → нормальный
```

Контракт сам проверяет: `if crisis_mode && now - crisis_activated_at > 1800 → use normal cooldown`

### Position Transfer (secondary market)

```
1. Seller: transfer_position(buyer_pubkey) → pending_transfer = buyer
2. Buyer: (будущее) accept_position() → ownership меняется, loyalty tier сохраняется
3. Seller может cancel_transfer() до принятия
```

### Role Separation

```
Роль           Может                    Не может
Authority      freeze, set_roles,       двигать деньги юзеров
               update guardrails
AI Agent       update_params, price,    withdraw, close accounts
               liquidate, freeze
Keeper         liquidate (+ reward)     менять параметры
```

`set_roles` позволяет authority назначить отдельные ключи для AI и keeper.
